# Original brief (as given by the owner) and follow-up requests

This is the product brief Designer Kid was built from, followed by every follow-up request made during the
build session (30 Sep 2026), in order. Where the build intentionally differs from the brief, see
"Decisions that changed the brief" at the bottom.

---

## Part 1 — The original brief

Build a complete **Designer Kid Learning & Career Platform** — not a static learning website, but a polished,
futuristic, interactive learning platform for UI/UX designers at different career stages. Think like a Senior
Product Designer, Senior UX/UI Designer, UX Educator, Design System Designer, Product Strategist, UX Researcher
and Frontend Product Engineer. Don't blindly follow requirements if there are UX, usability, IA, accessibility
or product problems — improve the experience while preserving the core requirements.

1. **Product** — Brand *Designer Kid*, tagline *Learn. Design. Build. Grow.* Helps people learn UI/UX, build real
   projects, improve portfolios, prepare for jobs and keep growing. Three stages: **Beginner** (new to UI/UX),
   **Intermediate** (knows fundamentals, wants stronger product-design skills), **Expert** (advanced product,
   design-system, leadership and career content).
2. **First-time experience** — don't show the dashboard immediately. Onboarding asks *"Where are you in your
   design journey?"* with three large interactive cards (Beginner: "I'm starting my UI/UX journey";
   Intermediate: "I already know the basics"; Expert: "I'm an experienced designer"), each with illustration,
   description, recommended path, animated hover and CTA ("Continue as Beginner"). Remember the level; allow
   switching later.
3. **Principle** — content must genuinely differ per level: roadmap, courses, lessons, exercises, projects,
   resources, career guidance, challenges and progress tracking.
4. **Beginner content** — Module 01 UI/UX Fundamentals (What is UI/UX, UI vs UX, Product Design, roles, design
   thinking, user-centred design, process, visual hierarchy, layout, spacing, alignment, typography, colour,
   contrast, accessibility); 02 Figma Fundamentals (frames, layers, shapes, text, images, components, Auto
   Layout, constraints, variants, styles, variables, prototyping, libraries, Dev Mode) with every lesson as
   Learn → Example → Practice → Challenge; 03 UX Process (problem statements, personas, research, interviews,
   affinity mapping, journeys, IA, flows, wireframes, prototypes, usability testing, iteration); 04 UI Design
   (typography, colour systems, grids, spacing systems, components, buttons, forms, cards, navigation, tables,
   dashboards, empty/loading/error states, responsive, accessibility); 05 Projects (login/onboarding, mobile
   app, responsive landing page, dashboard); 06 Portfolio (case studies, decisions, process, research,
   wireframes, final UI, iterations); 07 Career Starter (portfolio, LinkedIn creation/headline/About/Featured,
   job search, applications, recruiter messages, networking, interview prep).
5. **Intermediate content** (no repetition of beginner material) — Product Thinking, UX Research, Information
   Architecture, Advanced UI, Design Systems, Product Design (Problem → Research → Strategy → UX → UI →
   Prototype → Testing → Iteration), Portfolio (stronger case studies, storytelling, impact, trade-offs),
   Career (resume/LinkedIn optimisation, portfolio review, recruiters, interviews, design exercises, product
   design interviews, salary negotiation fundamentals).
6. **Expert content** — Product Strategy, Advanced UX (enterprise workflows, multi-role, permissions, IA at
   scale, behavioural patterns, research strategy, service design), Design Systems at scale (governance,
   contribution, adoption, versioning, metrics), Leadership (critique, mentoring, reviews, stakeholders, PMs,
   engineers, presenting to leadership, conflicting feedback, managing teams), Career Growth (Senior/Lead/
   Staff expectations, leadership, senior portfolios, interviewing, mentoring, personal brand, thought
   leadership).
7. **Learning dashboard** — "Welcome back, [Name]", "Your level", Continue Learning, progress (overall, module,
   lessons, projects, streak, achievements), visual roadmap (Foundation → Figma → UX → UI → Projects →
   Portfolio → Career) where completed modules change and locked modules explain what to complete first.
8. **Lesson page** — header (module, lesson, time, difficulty), clear explanations, visual & interactive
   examples, do/don't, checklists, mini exercises, Practice assignment, Challenge task, Mark as Complete →
   Next Lesson.
9. **Design challenges** — categories UI, UX, Figma, UX research, Design system, Product thinking, Portfolio;
   each with brief, context, requirements, constraints, expected outcome, difficulty, time, submission area and
   self-review checklist.
10. **Resume guidance** — structure, summary, skills, experience, projects, education, achievements; honest,
    outcome-focused bullets (no fake metrics/experience); checklist: clear role, relevant skills, portfolio link,
    LinkedIn link, strong projects, consistent formatting, no spelling mistakes.
11. **LinkedIn guidance** — photo, banner, headline, About, experience, projects, Featured, skills, education,
    Open to Work, with examples and why each matters; LinkedIn checklist; content ideas (learning, project
    breakdowns, before/after redesigns, UX lessons, Figma tips, case-study progress, challenges, career lessons).
12. **Portfolio guidance** — homepage, case studies, about, contact; case-study template: Problem → Research →
    Insights → User Flow → Wireframes → Design System → UI → Testing → Iteration → Outcome → Learnings.
13. **Career Centre** — Resume, LinkedIn, Portfolio, Job Search, Interview Prep, Design Challenges, Networking,
    each with progress indicators.
14. **1:1 Connect with Harikrishna** — "Request a 1:1 session" for portfolio/resume/LinkedIn reviews, career
    guidance, UI/UX doubts, Figma help, interview prep, project feedback, mentorship; simple flow; admin manages
    requests (approve, reject, reschedule, complete, notes, availability, duration, days, time slots).
15. **Admin dashboard** — totals per level, active learners, completed courses, completion rate, challenge
    submissions, 1:1 requests, recent activity; meaningful analytics, not decorative charts.
16. **Content management** — create/edit/delete (with confirmation)/reorder (drag & drop) courses, modules,
    lessons, challenges, resources, career guides, announcements; edit title, description, content, images,
    videos, links, exercises, difficulty, time.
17. **Level management** — enable/disable, rename, description, icon, colour, roadmap, modules, recommended path.
18. **Website content controls** — homepage (hero, CTA, images, features, testimonials, stats, FAQ),
    navigation (items, labels, links, visibility), footer (links, social, copyright, contact).
19. **Theme editor** — logo, favicon, brand name, tagline; colours (primary, secondary, accent, background,
    surface, text); typography (heading/body font, size, weight, line height); radii, shadows, borders; light /
    dark / system; live preview before publishing.
20. **Media management** — upload/replace/delete images, thumbnails, illustrations, profile images, course media
    with previews and metadata.
21. **Publishing** — Draft → Preview → Publish; save draft, preview, publish, unpublish, restore previous
    version; confirmation before major changes.
22. **User management** — name, email, level, progress, lessons, projects, challenge activity, 1:1 requests,
    registration date; search and filters.
23. **1:1 management** — Pending / Confirmed / Completed / Cancelled with student, email, topic, message, date,
    time, status, admin notes.
24. **Notifications** — new lesson, new challenge, course completion, 1:1 request, announcements, career updates;
    admin creates announcements.
25. **Futuristic UI** — careful glassmorphism, soft gradients, large type, dark/light, subtle glow, floating
    cards, layered UI, micro-interactions, smooth transitions, playful illustrations, depth — "Figma + modern
    learning platform + creative studio" with a unique identity; usability over effects; avoid excessive neon,
    blur, animation, tiny text, poor contrast, overloaded dashboards.
26. **Animation** with Motion — page/modal/sidebar transitions, card hover, level selection, progress, toasts,
    loading, scroll reveals, micro-interactions; smooth, purposeful, fast, subtle, accessible; respect reduced
    motion.
27. **Motion Studio** — install per https://motion.dev/docs/studio (Motion ≥ 13.3.0, Node ≥ 22.13), dev
    dependency, correct plugin for the build setup, no hard-coded credentials; verify it loads, an animation
    appears, a timing change can be previewed, and production excludes it.
28. **UI/UX Pro Max** skill — use it for design system, typography, colour, spacing, components, patterns,
    responsive, accessibility, interaction, hierarchy, consistency (don't follow blindly).
29. **Responsive** — desktop (full nav, sidebar), tablet (condensed nav, adaptive grid), mobile (bottom nav,
    collapsible sections, touch-friendly, simplified admin) — designed intentionally, not shrunk.
30. **Accessibility** — contrast, keyboard, focus states, semantics, accessible buttons/forms/labels, reduced
    motion, readable type, touch targets.
31. **Global search** — courses, lessons, challenges, resources, career guides; category, level, title,
    description; filter by level.
32. **Bookmarks** — lessons, resources, challenges, career guides → My Bookmarks.
33. **Notes** — private notes per lesson, viewable later.
34. **Progress** — lessons, courses, challenges, projects, streak, overall; personalise the dashboard.
35. **Achievements** — meaningful (First Step, Figma Explorer, UX Thinker, Case Study Builder, Portfolio Ready…).
36. **Content quality** — beginner-friendly where needed, progressively advanced, real examples, practical
    exercises, explain WHY, little jargon; no unrealistic promises, fake statistics or fake testimonials.
37. **IA** — Home, Learn (levels), Challenges, Career (Resume, LinkedIn, Portfolio, Interviews, Job Search),
    Resources, My Progress, 1:1 Connect, Profile; admin: Dashboard, Content, Courses, Levels, Challenges, Users,
    Analytics, 1:1 Requests, Media, Theme, Settings.
38. **UX principle** — don't overwhelm beginners; progressive disclosure.
39. **Final experience** — Welcome → level → personalised dashboard → recommended path → lessons → projects &
    challenges → portfolio/resume/LinkedIn/career → 1:1; "What should I do next?" always obvious.
40. **Build rules** — inspect the project first, reuse, don't rewrite working code, keep config, test key
    flows, no fake functionality; separate the data layer if no backend exists.
41. **Admin-first content architecture** — Level → Course → Module → Lesson → Exercise → Challenge → Resource,
    consumed dynamically (no hard-coded page content).
42. **Admin preview** — Edit → Preview → Publish showing exactly what students see.
43. **Final design review** — UX, UI, responsive, accessibility, content, admin, performance.
44. **Don't stop at the landing page** — full student journey and admin journey.
45. **Success criteria** — students can answer: where to start, what next, what to practise, progress, portfolio,
    resume, LinkedIn, interviews, how to get help; admin can change content, lessons, challenges, paths,
    homepage, colours/fonts/images, manage students and 1:1 requests, preview, see activity.

## Part 2 — Follow-up requests during the session (chronological)

1. "Create a new folder." → project created at `designer-kid/`.
2. Use the **GitHub free plan**; suggest GitHub Marketplace plugins. **1:1 session = just a link** that redirects
   to an external tool, editable in the admin panel.
3. Chose **Supabase free tier** for data (over browser-only).
4. Shared Supabase publishable keys/URLs (final project: `zcxnlelzhkwbvittgcuj`).
5. **Content files must stay open** — users can open any file at any time (no locking).
6. **PowerPoint-like editing** in admin; **upload PDF or PPT**; students **download content as PDF**; more
   visually appealing content with **themed illustrations** and good examples; **interview Q&A**, **LinkedIn
   do's & don'ts**, **resume creation guidance**; everything replaceable in admin.
7. **Reviews about Harikrishna** written by users, controlled in admin.
8. Host on **GitHub first**, then connect Supabase admin. (GitHub login via device code in Safari.)
9. Add admin features: **offer banner/pop-up when users land**, edit **logos, favicons, theming**, edit
   **blogs** and everything, publish.
10. Add **design blogs**, show them on the **dashboard**; make **1:1 visible on the landing page**; user
    **accounts with login**, admin control of users, **password reset by email**; asked about **cost**.
11. **Dropped user accounts**: keep the site open, save learner data in the **browser**; finalise and publish
    everything live; produce a **downloadable zip with all code and full documentation/memory** for other AI
    agents or humans.

## Decisions that changed the brief (and why)

| Brief | What was built | Why |
|---|---|---|
| 1:1 request form + admin approve/reschedule/slots | External booking link (Calendly/Cal.com/Topmate) + click analytics | Owner's decision (request 2) — scheduling tools already do this well and for free |
| Locked modules | Everything open; optional "suggested order" hint | Owner's decision (request 5) |
| Student accounts & admin user management | Built, then **removed from the student UI** — progress stays in the browser with backup/restore; admin accounts only | Owner's decision (request 11) — no sign-up friction, no email cost/limits |
| "Download as PDF" | Print-optimised pages + browser "Save as PDF" | Sharp, selectable text with the same illustrations; no heavy PDF library |
| Upload PPT and edit like PowerPoint | PPT/PDF uploads are attached/embedded (PDF inline; PPT via Office viewer when public) — they are **not** converted into editable slides | Converting PPTX to editable blocks needs a server-side conversion service |
| UI/UX Pro Max skill | Not installed (needs the owner to run `/plugin` commands) | Tool limitation; design review was done manually and with automated contrast checks |
| Motion Studio "timing change can be previewed" | Studio verified loading + timeline showing an animation; timing edit not automated | Requires manual interaction in the Studio panel |
